# Equivalent mutants

A mutant is equivalent when no test can tell it from the original code. Each entry below needs the maintainer's approval through the merge, and each needs a reason showing why no test can distinguish the mutant from the original. `cargo xtask mutants-check` fails the mutation job on any missed mutant that is not listed here.

Each row covers one missed occurrence. Two identical equivalent mutants need two identical rows. A row listed more often than the mutant is missed is reported as stale in full runs.

The `mutation` column is the description cargo-mutants prints, with the `:line:col` removed from the location, for example `replace == with != in matches_segment`. When a description contains the pipe character, escape each pipe with a backslash inside the table, because an unescaped pipe ends the cell.

| file | mutation | reason |
| --- | --- | --- |
| src/cache.rs | replace * with + | The constant sets the size of the read buffer in `hash_file`, which only decides how many `read` calls feed the same byte sequence to SHA-256. The digest of a byte sequence does not depend on how it is chunked, so no test can observe the buffer size. |
| src/aimed.rs | replace < with <= in phrase_hits | With `at == tokens.len()` the loop calls `match_at`, which needs `alt_matches` on the range `at..at + alt.len()`. `alt_matches` rejects an empty alternative and `tokens.get` returns None for a range that starts at the length and ends past it, so `match_at` returns None, `at` is incremented and the loop ends. The extra iteration records no hit. |
| src/aimed.rs | replace < with > in dialogue_hit | In the `\r\n` branch, `next < chars.len()` is replaced by `next > chars.len()`, which is never true, so a CRLF pair is not collapsed. The uncollapsed form sets `line_start` to the `\n` itself. That one extra line starts with a line terminator, so `at` stays on it, neither marker (both begin with a letter) matches, `next` stays on it and `line_start` moves past it. The extra line changes neither `human` nor `assistant`, and the loop ends in the same place. |
| src/aimed.rs | replace == with != in dialogue_hit | The condition `chars[next] != '\r' && chars.get(next + 1) == Some('\n')` is true only for a line terminator other than `\r` followed by `\n`, and false for a CRLF pair. For a CRLF pair, not collapsing is the same as the original (see the row for `<` replaced by `>`). When it is true, the extra `next += 1` skips only the `\n` that follows, and the line that would start at that `\n` is empty (it starts with a terminator, so no marker matches). Skipping it changes nothing. |
| src/aimed.rs | replace + with * in dialogue_hit | In `chars.get(next + 1)` the mutant reads `chars.get(next * 1)`, which is `chars[next]`. That is the `\r` the condition has just matched, never `\n`, so a CRLF pair is not collapsed. Not collapsing is the same as the original (see the row for `<` replaced by `>`). |
| src/aimed.rs | replace += with *= in dialogue_hit | `next *= 1` leaves `next` unchanged, which is the same as not collapsing a CRLF pair. Not collapsing is the same as the original (see the row for `<` replaced by `>`). |
| src/glob.rs | replace + with * in segment_matches | In `token = star + 1` the mutant gives `token = star`. After a mismatch with a pending `*`, `resume` and `at` are set as before. If `at < text.len()`, the next iteration reads `tokens[star]`, which is the `AnyRun`, sets `resume = Some((star, at))`, which is the value it already holds, and moves to `star + 1`, so the state equals the original state. If `at == text.len()`, the loop ends and the final check `tokens[star..].iter().all(AnyRun)` holds exactly when `tokens[star + 1..]` is all `AnyRun`, because `tokens[star]` is `AnyRun`. |
| src/glob.rs | replace + with * in segment_matches | In `at = from + 1` the mutant gives `at = from`, so the tokens after the pending `*` are tried once more at the same text position. The state is `(star + 1, from)` exactly as when the `*` was first passed, and no `AnyRun` lies between `star + 1` and the earlier mismatch (it would have become the pending `*`), so the retry fails at the same place and takes the same branch, and `resume` has moved on to `from + 1`. The next iteration then continues as the original does. Every mismatch still advances `resume`, so the loop ends, and the result is the same for every pattern and text. |
| src/encoded.rs | replace + with * in find_uris | In `i = j.max(i + 1)` after a data prefix without a comma, `j` starts at `i + 5` and is only ever incremented, so `j >= i + 5`. The mutant gives `j.max(i * 1)` which is `j.max(i)`. Both are `j` because `j > i + 1`, so the value of `i` and every later step are the same for every input, and no direct test of `find_uris` can tell them apart. |
| src/encoded.rs | replace + with * in find_uris | In `i = end.max(i + 1)` after a data URI is recorded, `end` is `base64_prefix_end(chars, j + 1, ..)` or `payload_end(chars, i, j + 1, ..)`. Both start their index at `j + 1` and only move it forward, including the early return when the ticker expires, so `end >= j + 1 >= i + 6`. The mutant gives `end.max(i * 1)`, which is `end.max(i)`. Both are `end` because `end > i + 1`, so no input separates them. |
| src/encoded.rs | replace \| with ^ in decode_base64 | In `(acc << 6 \| value) & 0xFFFF` the left operand `acc << 6` has its low six bits clear, and `value` comes from `base64_value`, which returns only 0 to 63, so the operands share no set bit. For operands with no common bit, `\|` and `^` give the same result for every input, and `decode_base64` has no other source for `value`. |
